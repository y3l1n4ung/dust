# Internationalization

Dust scans static translation keys, maintains ARB files, and generates the
Flutter bootstrap used to load and switch locales.

## Add the Package

Install the Dust CLI from the [root guide](../../README.md#installation), then
add the Flutter runtime:

```bash
flutter pub add dust_flutter
```

Add Flutter's localization SDK package to `pubspec.yaml`:

```yaml
dependencies:
  flutter_localizations:
    sdk: flutter
```

## Quick Start

Configure locales in `dust.yaml`. The first locale is the fallback and source
locale:

```yaml
i18n:
  locales: [en, fil]
```

Use an ARB-safe key with a namespace prefix:

```dart
import 'package:dust_flutter/i18n.dart';

const TranslatedText(
  'recording_empty',
  defaultText: 'No recording yet',
)
```

Generate the ARB files and Flutter bootstrap:

```bash
dust i18n build
```

Dust writes:

```text
assets/i18n/en/recording.arb
assets/i18n/fil/recording.arb
lib/i18n/app_i18n.g.dart
```

Declare each locale directory as a Flutter asset:

```yaml
flutter:
  assets:
    - assets/i18n/en/
    - assets/i18n/fil/
```

Wrap the application with the generated loader:

```dart
import 'package:dust_flutter/i18n.dart';
import 'package:flutter/material.dart';

import 'i18n/app_i18n.g.dart';

void main() {
  runApp(const AppI18n(child: App()));
}
```

Connect the same controller to Flutter's framework localizations:

```dart
class App extends StatelessWidget {
  const App({super.key});

  @override
  Widget build(BuildContext context) {
    final i18n = I18nScope.of(context);

    return MaterialApp(
      locale: appI18nLocaleOf(i18n.locale),
      supportedLocales: appI18nSupportedLocales,
      localizationsDelegates: appI18nLocalizationsDelegates,
      home: const HomePage(),
    );
  }
}
```

> [!IMPORTANT]
> `assets/i18n/` alone does not include files inside its locale
> subdirectories. Declare every locale directory or list each ARB file.

## Keys and Namespaces

Static keys must start with a letter and contain only letters, numbers, and
underscores. The text before the first underscore is the namespace and ARB file
name:

| Dart key | ARB file | ARB message key |
| :--- | :--- | :--- |
| `shop_title` | `shop.arb` | `title` |
| `shop_product_price` | `shop.arb` | `product_price` |
| `login_submit_button` | `login.arb` | `submit_button` |

Use literal keys with `TranslatedText` and `context.tr` so Dust can find them:

```dart
TranslatedText(
  'shop_product_price',
  defaultText: r'${price}',
  args: {'price': price.toStringAsFixed(2)},
)
```

```dart
final hint = context.tr(
  'shop_search_hint',
  defaultText: 'Search products',
);
```

Placeholders use `{name}` and every statically visible argument becomes ARB
placeholder metadata. Dust adds examples but does not guess semantic ARB types.

## Translation Preservation

Normal `dust i18n build` is additive. It creates missing messages and metadata
without replacing existing message text.

| ARB state | Normal build behavior |
| :--- | :--- |
| Missing fallback-locale key | Adds `defaultText`, or the full key when no default exists. |
| Existing fallback-locale key | Preserves the existing value. |
| Missing non-fallback key | Adds an empty string for translation. |
| Existing non-fallback key | Preserves the translation. |
| Existing metadata | Preserves custom fields and fills required missing fields. |

For example, changing Dart source from `No recording` to `No recording yet`
does not replace an existing Filipino translation:

```json
{
  "empty": "Wala pang recording"
}
```

`defaultText` is source fallback copy, not the source of truth for translated
locales.

> [!IMPORTANT]
> A newly added non-fallback message is intentionally empty. Translate it
> before running `dust i18n check`, because the checker rejects empty messages.

## Updating Source Copy

When source copy intentionally changes, preview updates to the first configured
locale:

```bash
dust i18n build --sync-source --dry-run
```

Apply the reviewed source-locale changes:

```bash
dust i18n build --sync-source
```

Source sync changes only existing fallback-locale messages that have a scanned
`defaultText`. It never changes non-fallback translations.

> [!TIP]
> Review and commit source-locale ARB changes before sending updated copy for
> translation. This keeps intentional copy updates separate from translated
> values.

## CLI Workflow

| Command | Behavior |
| :--- | :--- |
| `dust i18n scan` | Lists static keys, namespaces, default text, and placeholders without writing. |
| `dust i18n build` | Scans source, reconciles ARB files, and refreshes the generated bootstrap. |
| `dust i18n check` | Validates ARB files, assets, placeholders, and optional iOS metadata without writing. |

The scanner ignores `TranslatedText.dynamic(...)` and warns about runtime keys
passed to static APIs. It also reports hardcoded `Text('...')` strings found in
scanned Flutter source.

The checker rejects invalid JSON, missing locale files or keys, empty messages,
missing metadata, placeholder mismatches, and missing Flutter asset
declarations. It warns about stale keys and non-fallback values that match the
fallback locale.

## Dynamic Keys

Use the dynamic constructor when a key comes from an API, CMS, or model:

```dart
TranslatedText.dynamic(
  promotion.titleKey,
  fallback: promotion.fallbackTitle,
)
```

Dynamic keys are runtime-only and are not added to ARB files by the static
scanner.

## Switching Locales

Change the active locale through the controller:

```dart
I18nScope.of(context).setLocale('fil');
```

Widgets that read `I18nScope` rebuild after the locale changes. The selected
locale must be present in `i18n.locales`.

Locale values such as `en_US` and `zh_Hans_CN` are generated with language,
region, and script subtags for Flutter.

## Runtime Overrides

Remote JSON or ARB messages can replace one namespace at runtime:

```dart
final source = await api.getText('/i18n/fil/recording.arb');

I18nScope.of(context).applyOverrideBundle(
  source,
  locale: 'fil',
  namespace: 'recording',
);
```

Metadata keys beginning with `@` are ignored by the runtime parser. Overrides
remain active until replaced or cleared.

> [!NOTE]
> Runtime overrides currently apply globally by full translation key. Replace
> or clear locale-specific overrides when the active locale changes.

## iOS Locale Metadata

Flutter uses the generated Dart locale list. Native iOS bundle metadata is
optional. Enable synchronization when the app also needs
`CFBundleLocalizations` in `Info.plist`:

```yaml
i18n:
  locales: [en, fil, zh_Hans_CN]
  ios:
    info_plist: ios/Runner/Info.plist
    sync_development_region: true
```

`dust i18n build` writes Apple-style identifiers such as `zh-Hans-CN` while
preserving unrelated plist values. `sync_development_region` also sets
`CFBundleDevelopmentRegion` to the first configured locale. `dust i18n check`
reports stale plist metadata without modifying it.

> [!NOTE]
> iOS plist metadata does not replace `supportedLocales` or localization
> delegates in `MaterialApp`.

## Lookup Order

Dust resolves messages in this order:

1. Runtime override.
2. Active-locale bundle.
3. Fallback-locale bundle.
4. `defaultText` or dynamic `fallback`.
5. The key itself.

ICU plural and select messages are not currently supported.
